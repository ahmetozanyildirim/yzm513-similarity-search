# High-Performance Similarity Search Engine

**YZM 513 – High-Performance Programming for AI · Project 1** · [Türkçe](README_TR.md)

Given 20,000 recent arXiv abstracts (cs.AI / cs.CL / cs.LG, Jan 2025 – Sep 2026) and 200 queries, return the top-10 most
similar documents for every query — and make it fast. We start from a pure-Python baseline, profile it, and remove the
bottlenecks one by one (vectorisation, Numba, dimensionality reduction, parallelism), verifying every version against the
baseline with tolerance 1e-5.

* Report: [`report/REPORT.md`](report/REPORT.md) (PDF: `report/REPORT.pdf`) · Turkish: [`report/RAPOR.md`](report/RAPOR.md)
* All figures and raw benchmark data: [`results/`](results/) (one folder per project phase)

| | |
|---|---|
| Dataset | arXiv API, 20,000 abstracts (documents) + 200 paper titles (queries); the matching abstract is the known answer |
| Embeddings | `sentence-transformers/all-mpnet-base-v2`, 768-d, float32 (generation time is not benchmarked) |
| Final system | normalise once → TruncatedSVD to 128-d → batched BLAS search → parallel Numba top-k (100 candidates) → exact 768-d re-rank → top-10 |
| Hardware used | AMD Ryzen 7 9800X3D (8 cores / 16 threads, 96 MB L3), 32 GB RAM, Windows 11, Python 3.12 |

python scripts/prepare_data.py         # ~10 min download + ~40 min embedding on a laptop CPU (1-2 min on a GPU); cached

## Benchmark methodology

* Every timing: warm-up runs (3 for anything JIT-compiled) + **at least 5 timed runs**; the **median** is reported
  (mean, std and raw times are in `results/`).
* Same machine, same data and queries for every version. BLAS / Numba thread counts are set explicitly where a comparison
  needs it (e.g. single-threaded in Phase 2A).
* Correctness: every optimised version is compared rank by rank with the naive baseline (`results/1_baseline/baseline_topk.npz`)
  with tolerance 1e-5 (`hpss.bench.compare_topk`).
* Embedding generation and index construction (normalisation, SVD fit, inverted index) happen once and are reported separately;
  only search time is benchmarked.
* `import hpss` sets `OMP_WAIT_POLICY=PASSIVE` / `KMP_BLOCKTIME=0` so that idle Numba (OpenMP) threads sleep instead of spinning
  and stealing cores from OpenBLAS (measured in phase 4; set `HPSS_NO_THREAD_FIX=1` to disable).
* Close other CPU-heavy programs while benchmarking.
